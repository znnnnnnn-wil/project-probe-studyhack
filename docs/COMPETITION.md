# StudyHack 参赛准备

作品：项目追问官。

一句话：帮助准备技术实习的学生，围绕自己的项目练习连续追问，回看原回答与材料依据，整理下一步要补充的实现与验证。

官方赛事页面：https://tianchi.aliyun.com/competition/entrance/532536

## 三分钟演示

1. 0:00–0:25：说明痛点。学生简历上写了项目，但连续追问时说不清职责、执行顺序或验证结果。
2. 0:25–1:00 打开免登录短体验，使用「只讲约束」，展示为什么下一题会问接口如何反馈冲突。
3. 1:00–1:35 换成「讲清冲突响应」，展示下一题如何转向并发测试。说明分支由本地规则决定。
4. 1:35–2:10 补充并发测试输入和预期结果，展示两次回答的对照。实际测试结果仍需核对。
5. 2:10–2:40 从示例项目打开正式语音面试室，再进入访客训练记录，展示预先完成的一场面试的原复盘、专项复测和导出。
6. 2:40–3:00：说明已经完成的用户试用与发现，仅填写真实记录。展示实际使用 Qoder 的开发、修改、验证和部署证据。

## 当前交付边界

- 首页与快捷追问演示可作为静态网页部署。
- 免登录示例和自有项目共用语音面试、模型和历史记录服务，部署需接通 Spring Boot 后端、数据库及同源 `/api`。
- 当前没有真实模型验收、真实学生试用结果或本次 Qoder 使用记录，不宣称已经完成这些事项。
- 没有把现成作品重新部署就描述为全新开发；应如实说明旧项目基础与本次改造分工。

## 提交前需要实际完成

- 在 Qoder 打开本目录，围绕真实需求完成后续开发、调试、体验改进并保留过程记录。
- 配置并验收自己的真实模型，如计划对评委开放，设置可控的调用额度和故障提示。
- 选择实际可用的后端托管与代理方案；在 Qoder Sites 部署并验证公开访问、路由刷新、核心交互和手机端体验。
- 请几位目标用户试用，记录具体卡点、修改与结果；不提前填写人数、效果比例或节省时间。
- 完成赛事要求的认证与作品帖，核对官网最新要求和截止时间。

实习权益应表述为官网所述的“内推机会”，不承诺获得面试或录用。
