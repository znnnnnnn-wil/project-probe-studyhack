# 项目追问官：产品设计文档

版本：V1.0  
更新时间：2026-11-23

目标赛道：StudyHack 学习科研  
当前阶段：参赛体验版已通过 Qoder Sites 公开发布。

## 1. 产品定位

帮助准备技术实习的学生，围绕自己实际参与的项目练习连续追问，通过可回看的原回答和材料依据，发现解释缺口并整理下一步行动。

产品承诺是提供练习过程与可核对的反馈，不承诺面试通过、实习内推或录用。

## 2. 用户与问题

核心用户是准备后端或 Agent 应用开发实习的在校学生：做过项目，但不擅长解释个人职责、关键实现、失败边界与验证过程。

| 场景 | 当前困难 | 希望得到的结果 |
| --- | --- | --- |
| 面试前整理项目 | 简历只写了技术名词，讲不出执行过程 | 能用自己的语言解释具体步骤 |
| 被连续追问 | 能回答第一题，但难以解释下一层细节 | 在练习中提前暴露解释缺口 |
| 阅读 AI 反馈 | 建议笼统，难以判断依据 | 回到原回答与项目材料核对 |
| 练习结束 | 不知道下一步应该补什么 | 得到具体任务并留下笔记 |

需求假设需要通过真实学生试用验证，当前不声称已有用户规模或效果提升数据。

## 3. 产品目标

1. 首次访问者可以直接使用预填项目完成五轮语音练习，并在当前浏览器查看训练记录。
2. 用户能够围绕每个项目完成一轮五题练习，并能再次练习和回看历次复盘。
3. 报告保留原问答和材料引用，让每个反馈有可核对的上下文。
4. 在模型、网络或刷新发生异常时，尽可能保留已提交回答和当前进度。
5. 清楚区分规则演示、真实模型输出、用户自述和已经独立验证的结果。

首版不覆盖自动投递、招聘信息爬取、视频面试、简历代写或自动执行任意仓库。

## 4. 两条核心体验

### 4.1 免登录示例

首页 → 选择合成项目 → 进入面试室 → 五轮语音问答 → 查看报告、复测和完整对话。

示例包括校园预约系统、课程资料 RAG 问答助手和定时通知服务。示例和自有项目共用题目生成、答疑、复盘和专项复测。已有的旧版示例可从同一标签页继续查看。

### 4.2 自有项目训练

注册或登录 → 手动填写项目或上传简历识别项目 → 核对并保存 → 开始五轮项目追问 → 查看引用与任务 → 导出复盘。

每轮五题共用开练时保存的材料快照。用户可以为不同项目分别开始练习，也可以在完成后用当前项目材料开始新一轮。

本地默认使用规则模式。配置真实模型后，系统根据项目与已提交回答生成后续问题，并校验报告引用。

训练记录可继续未完的练习，也可打开某一轮的复盘。完成后可选一条反馈和它引用的原回答，补答原问题并查看对照。原报告和复测结果一起保存和导出。规则模式识别补答中标注的细节，模型模式沿用原文引用校验。

## 5. 页面与信息结构

| 页面 | 主要信息 | 核心操作 |
| --- | --- | --- |
| 首页 | 产品价值、追问示意、三个场景、模式说明 | 免登录体验、使用自己的项目 |
| 场景选择 | 项目背景、技术栈、合成材料说明 | 选择项目、开始练习 |
| 示例项目 | 预填项目材料 | 进入面试室、查看训练记录 |
| 账号工作台 | 项目列表 | 创建项目或直接进入面试室 |
| 新建项目 | 手动输入表单、简历识别结果 | 填写材料、编辑识别结果并批量保存 |
| 项目编辑 | 项目材料、个人职责 | 保存项目材料 |
| 面试室 | 可选主题与五轮问答 | 指定准备方向，或由系统按项目材料出题 |
| 训练记录 | 各项目的训练轮次与进度 | 继续当前训练、回看历次复盘 |
| 自有项目反馈 | 原问答、反馈方向、引用依据、补充任务 | 导出、补充材料、记录体验反馈 |
| 账户与数据 | 账号恢复、项目和缓存清理 | 管理本人数据 |

## 6. 交互原则

- 每题聚焦一个可以解释清楚的目标，逐步向实现细节推进。
- 用户可以直接说不会、没有做过或尚未验证，不强迫补写经历。
- 新增条件应标明是假设，不把面试问题中的设定当作用户经历。
- 当前问题与历史问答有明确区分，回看旧回答不能覆盖当前草稿。
- 只有用户明确提交后，回答才进入正式问答记录。
- 自查勾选代表用户自行核对，不代表系统完成技术验证。
- 手机端将材料和对话改为上下布局，按钮和输入区域保持可用。

## 7. 状态与异常处理

| 状态 | 用户看到什么 | 行为约束 |
| --- | --- | --- |
| 尚未开始 | 材料与开始按钮 | 不提前生成报告 |
| 等待回答 | 当前题目、草稿、提交入口 | 空白回答不能提交 |
| 正在生成 | 处理中与进度恢复提示 | 不重复提交，读取当前状态 |
| 生成失败 | 明确错误与恢复入口 | 保留原回答，不伪装成功 |
| 已完成 | 完整问答、复盘、开启新一轮入口 | 开始新一轮后仍可回看原复盘 |
| 后端不可用 | 首页可打开，面试显示连接问题 | 用户可重试连接 |
| 浏览器存储不可用 | 提醒刷新可能丢失进度 | 保持本轮可操作并允许导出 |

自有项目提交校验题目 ID，旧页面不能把上一题回答写入下一题。生成使用租约和令牌，过期后可恢复，旧执行器不能覆盖新状态。

## 8. 数据与依据

核心数据对象为项目材料、材料快照、训练轮次、问题、原回答、反馈发现、引用片段和补充笔记。

| 内容 | 来源 | 对外表述 |
| --- | --- | --- |
| 项目材料与回答 | 用户输入 | 用户自述，未经独立验证 |
| 示例材料 | 预设合成内容 | 合成示例，不代表用户实际经历 |
| 固定追问与自查任务 | 本地规则 | 练习引导，非 AI 技术评估 |
| 模型反馈 | 配置的模型服务 | AI 建议，仍需核对 |
| 引用检查 | 服务端原文定位校验 | 引用可定位，不等于结论已经成立 |

后端不把材料中的指令当作系统指令，也不执行材料内的代码。缺失信息保留待确认，不编造性能、用户数或个人成果。

## 9. 技术方案

- 前端：React、TypeScript、Vite，路由采用 Hash 方式，支持静态站点访问。
- 示例：访客会话和预填材料，共用面试服务。
- 后端：Java 17、Spring Boot、Flyway；本地默认 H2，保留 PostgreSQL 配置能力。
- 模型：服务端 OpenAI 兼容接口适配，密钥不进入前端构建。
- 身份：账号会话与用户归属校验，项目内容按账号隔离。
- 交付：Qoder Sites 托管静态前端，公开站通过独立的 HTTPS API 访问面试和训练记录。本地开发通过 Vite 代理访问后端。

## 10. 隐私与发布边界

示例问答、报告和复测保存在访客会话中，自首次进入起可在同一浏览器查看 30 天。旧版示例保存在开始练习时的标签页。

账号模式会将材料与回答保存到后端。启用真实模型时，相关内容会发送给配置的模型提供方，应向用户说明处理范围。

仓库不提交真实密钥、私有环境配置、运行数据库、用户简历、录音和测试运行产物。参赛发布应使用脱敏材料或合成示例。

公开部署与验收情况见[参赛准备](COMPETITION.md)。作品帖应说明沿用的项目基础和赛期工作，并附对应的 Qoder 开发记录。

## 11. 首版验收

1. 访客可从三个预填项目进入同一面试室，完成五题练习，以及回看训练记录。
2. 刷新后，当前题目、草稿、已提交回答和复盘笔记保持一致。
3. 示例和自有项目导出均包含本场问答、复盘和已完成的专项复测。
4. 同一账号可分别练习多个项目，同一项目开始新一轮后仍能回看上一轮报告。
5. 陈旧题目提交被拒绝，恢复生成不丢失或重复记录回答。
6. 后端用户隔离与材料快照规则有效，报告引用能够回到对应原文。
7. 手机端没有横向溢出，主操作可完成。

已有本地构建、后端定向测试和浏览器验收记录。公开站已用独立访客和示例参考回答完成五轮流程并打开复盘。真实学生的作答体验与模型反馈质量仍需试用评估。

## 12. 后续验证计划

先邀请少量准备技术实习的同学试用，观察能否独立开始、在哪一步停住、问题是否贴合项目，以及任务是否足够具体。

记录指标包括开始到完成的比例、完成耗时、用户认为偏题的问题、引用错误和用户是否愿意继续练习。指标需实测后填写，不预设增长或提升结论。

下一步根据学生试用记录修正流程，再通过公开站复验并补充作品说明。

## 13. 协作与变更规则

原版源码作为首次建仓基线。本次改造及后续工作均通过关联 Issue 的 PR 审阅，单个 PR 的新增行数与删除行数合计不超过 500。

PR 应说明用户可观察的行为变化、验收方式和已知限制；存在依赖时明确前置 PR，不通过压缩排版规避行数限制。
